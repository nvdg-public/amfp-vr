## Build and run
- Build: `src\build.bat [all|engine|game]`. Needs VS 2026 Community with "Desktop development with C++" (installed). Output is Win32 Release, toolset v145.

## Phase 6a: hand models (2026-10-08, confirmed in the headset by the tester)
- **Hands:** Godot XR Tools hand models (CC0, Miodrag Sejic; chosen by the tester; skin switched from "african realistic" to plain "african" after headset test 2). Source subset in `assets_src\hands\godot-xr-tools` (`SOURCE.txt` = repo commit). Rejected: Sclerosis/Auto Hand hands (not reusable), RRFreelance gloves (Asset Store licence forbids loose files).
- **Conversion:** `src\tools\hands\gltf2msh.py` (pure Python, no Blender/Assimp) writes MSH v7 directly (layout from `cMeshLoaderMSH::LoadMesh`, vertex elements like the game's own `models/player/hands/hands.msh`, tangents = port of `cMath::CreateTriTangentVectors`). `src\tools\hands\build_hands.bat` rebuilds `run\vr_assets\hands\` (vr_hand_l/r.msh, vr_hand.mat, PNG textures, License.md; in git). UVs used as-is (DevIL loads with upper-left origin); `--flip-v` exists if the texture looks wrong.
- **Model frame:** wrist at origin, fingers -Z, thumb +Y, palm -X (right) / +X (left), metres; 26 bones (OpenXR names), ~3k triangles.
- **Loading:** `cVRSystem::GetAssetDir()` (exe folder + `vr_assets`) is added as a resource dir on first use; `cLuxPlayerHands::UpdateVRHands` (called from `UpdateVRControllers`, per logic step and per rendered frame) creates one mesh entity per hand at the **aim (tip) pose** x `Hands HandOffset` (0.03 -0.04 0.14) / `HandRotation` (0 0 0), mirrored for the left hand. `ShowHands` default true; `ShowControllers` now defaults to false.
- **Fingers:** no animations. `SetupVRHandBones` finds 19 finger bones by name and a curl axis per bone (bone direction x palm normal, in the bone's frame); `PoseVRHandFingers` sets bone states to bind x rotation (fixed joint shares, `Hands FingerCurl` 85 deg when fully closed). Curls come from SteamVR's skeletal summary (new actions `skeleton_left/right` in `vr_actions.json` + knuckles bindings; `cVRSystem::GetFingerCurls`). Without skeletal data the right grip/trigger close the right hand. The lantern hand is forced closed (fingers 0.85, thumb 0.6) while the lantern is out.
- **Self-test:** both hand models load (26 bones, 19 finger bones), no new errors. Not visually checked (controllers untracked in the self-test; debug `HPL_VR_FAKE_HANDS=1` puts them in front of the seated head with the fingers opening and closing). `src\build.bat` does not copy the exe: copy `src\Game\redist\aamfp.exe` to `run\` after building.

## Phase 2 design decisions
- **Virtual screen:** in VR the engine's "screen" (framebuffer 0) is replaced by an eye-sized FBO per eye, so the whole pipeline (deferred renderer, post effects, GUI) renders unchanged. Screen size = eye render size; the desktop window is only a mirror (left eye, cropped).
- **Projection:** exact asymmetric (off-axis) per-eye frustum since 2026-10-08: `cFrustum` carries side tangents; all symmetric-FOV assumptions in the renderer were fixed (shaders didn't need changes). The old enclosing-symmetric + crop method stays as `Render Projection="Symmetric"` fallback (19% more pixels on the Index).
- **Camera:** gameplay camera untouched. Render eye = body position + body yaw (interpolated between 60 Hz logic steps, one step behind) x HMD pose x eye offset. Camera pitch/roll/FOV multipliers/shake rotation are ignored by the VR view. Mouse pitch still turns the (invisible) gameplay camera, which aims interaction; fix in Phase 3.
- **Frame pacing:** VR renders every compositor frame; engine FPS limiter and out-of-focus sleep are off in VR; logic still 60 Hz.
- **GUI:** 2D screen GUI rendered once per frame into a GUI panel texture shown as a SteamVR overlay fixed in seated space (Menu Distance/Width/Height in the cfg). Full-screen GUI objects (fades, flashes, full-screen images) are drawn in each eye instead. GUI draw lists must survive until the last eye pass.
- **Per-eye risks noted (not yet handled):** render frame counter increments per eye; occlusion queries and ImageTrail/motion-history effects may mix eyes. Check in headset; disable in VR if they misbehave.
- **Timing (Index 120 Hz, SteamVR recommended 3188x3540 = the tester's supersampling is high):** scale 1.0 (3869x3542/eye) ~9 ms, ~16% reprojected; scale 0.7 (2709x2480/eye) steady 8.33 ms.

## Phase 3 design decisions
- **Gameplay camera follows the head.** Every logic step (`cLuxPlayer::UpdateVRHead`, start of `Update`) the change in head yaw is added to the camera/body yaw (like mouse look, respecting yaw limits), pitch = head pitch, and the head position becomes `cCamera::SetHeadOffset` (`GetPosition()` includes it, `GetBasePosition()` doesn't). So the interaction ray, grab hold point, listener and enemy sight all use the real gaze. Turning (mouse X, stick, snap, script look-ats, teleports) changes the same camera/body yaw.
- **Render undoes it once:** for the player camera `cVRSystem::SetupEyeFrustum` uses body yaw = camera yaw - consumed head yaw, and the play-space origin = base position - rotated anchor; then applies the latest HMD pose. Interpolating the origin keeps room-scale steps smooth; yaw jumps > 15 deg (snap turns) are not interpolated.
- **Room-scale:** body follows the head's XZ offset (anchor in seated space, max 0.1 m per step, `CheckCharacterFits`, slides along an axis). Only in move state Normal and player states Normal/HandObject/UseItem.
- **Real crouch:** head below recenter height - CrouchDepth calls `cLuxMoveState_Normal::SetCrouch`; while the game lowers the camera, `SetHeadYAdd` takes the real drop back out (follows the game's own smooth crouch). MaxHeadRise caps the head above the recenter height.
- **Comfort (vr_settings.cfg):** mouse pitch ignored in VR (states still get it for levers); head bob off, screen shake x0.3, head spin off, look-at = one snap turn (pitch never forced), radial blur and image trail disabled (not written back to the flat game's settings). Game-side settings: `Game\src\game\LuxVR.h`.

## Gotchas learned
- Automated input on the tester's desktop is fragile. Only send it while the game window has focus, and never while the tester is playing.
- The engine resolves data relative to cwd, so run with cwd = game folder.
- The renderer assumed a symmetric FOV in several places; fixed 2026-10-08 (use `cFrustum` side tangents / `NearXToNormalized` for any new screen-space math).
- In HPL2, the camera view matrix and frustum feed game logic too (interaction ray, enemy sight, sanity). Apply the head pose to render cameras only.
- Shell escaping: writing paths like `sources\vr\...` through bash heredocs into Python turned `\v` into a vertical tab. Write patch scripts with the Write/Edit tools instead.
- `main_settings.cfg` has `LimitFPS="true" MaxFramesPerSec="60"`: without bypassing it VR runs at 60.
- The Claude app/other windows can steal focus: screenshots of the game need the game window in the foreground. For VR, use the capture env vars instead of screenshots.
- `02_mansion_02` starts with a scripted camera intro: two runs at the same frame number don't show the same view. Compare projections on the static main-menu scene.
- PowerShell `Remove-Item` on paths built from variables can be blocked by the harness; clear env vars with `[Environment]::SetEnvironmentVariable(name, $null, 'Process')`.
